# 프레임 단위 처리

README 핵심 성과 2번의 측정 기록

## 용어

- B: 라이브러리 없이 Nitro 콜백을 직접 구독하는 경로
- Q: 이 라이브러리의 큐 경로
- 표의 B / Q 칸은 같은 앱 실행 안에서 번갈아 측정한 값
- 핸들러: 가져온 이벤트를 처리하는 앱 코드
- 핸들러 오버: 이벤트 하나의 처리 시간을 발행 간격으로 나눈 값이며 1을 넘으면 처리가 이벤트를 따라가지 못함
- Batch: 큐에서 한 번에 가져온 이벤트 묶음
- 유입 시간: 핸들러 오버가 1을 넘어 처리보다 빠르게 들어오는 이벤트를 발행한 시간이며 기준은 워밍업 시작
- JS 스레드 지연: 10ms 간격 JS 타이머가 예정보다 늦게 실행된 시간이며 최대는 가장 늦게 실행된 한 번의 지연
- 이벤트 대기 시간: 이벤트 발행 시각부터 핸들러에서 처리가 시작되는 시각까지의 시간

## 결과

| 이벤트 | 처리 시간 | 플랫폼 | 최대 JS 스레드 지연 (ms) B / Q | 이벤트 대기 시간 중앙값 (ms) B / Q | 처리량 (건/초) B / Q |
|---|---|---|---|---|---|
| 센서 128B, 100/s | 12ms | iOS | 3,596 / 38.1 | 505 / 628 | 16.6 / 17.4 |
| 센서 128B, 200/s | 6ms | iOS | 3,597 / 20.1 | 506 / 565 | 33.4 / 34.1 |
| 센서 128B, 100/s | 12ms | Android | 615 / 74.2 | 513 / 517 | 16.8 / 16.8 |
| 센서 128B, 200/s | 6ms | Android | 609 / 38.1 | 521 / 520 | 33.8 / 33.6 |

- Android의 B 615ms는 3초 유입이 끝난 시점에 밀린 처리 시간 0.6초(3초 × 0.2)와 비슷하며 원인은 추정
- Android는 이벤트 대기 시간 중앙값과 처리량이 B와 비슷
- 핸들러 오버 0.9에서는 iOS의 Q 지연이 오히려 증가
	- iOS는 카메라 720p 최대 JS 스레드 지연이 B 24.0ms와 Q 49.6ms
	- Android는 같은 조건에서 B 28.5ms와 Q 30.3ms로 비슷
	- 주의: 핸들러 오버 0.9의 값은 위 표와 다른 카메라 720p 30/s 처리 측정에서 나온 값이며 B는 처리 대기 한도를 해제한 빌드로 측정
- 이벤트 대기 시간과 처리량은 측정 구간(2\~10초)에 발행된 이벤트만 집계
	- 3초 유입은 마지막 1초 분량
- 주의: 프레임 한도 14ms와 Batch 처리 한도 8ms는 첫 시도 값이며 iOS Q의 38.1ms는 이 값에서 나온 것으로 추정
- 주의: 처리 시간 12ms와 6ms는 합성한 핸들러이고 시뮬레이터와 에뮬레이터 속도라 실기기에서는 처리 시간이 더 길 가능성

## 측정의 한계

- 주의: 시뮬레이터와 에뮬레이터에서만 측정해 실제 앱의 JS 부하와 UI 프레임 영향은 확인 못함
- 주의: 센서 128B 100/s와 처리 시간 12ms는 실제 앱의 빈도와 부하를 측정한 값이 아니라 가정한 값
