# 큐 용량 제한

README 핵심 성과 3번의 측정 기록

## 용어

- B: 라이브러리 없이 Nitro 콜백을 직접 구독하는 경로
- Q: 이 라이브러리의 큐 경로
- 표의 B / Q 칸은 같은 앱 실행 안에서 번갈아 측정한 값
- 핸들러: 가져온 이벤트를 처리하는 앱 코드
- JS 막힘: 핸들러와 무관한 작업이 JS 스레드를 막는 시간
- 이벤트 대기 시간: 이벤트 발행 시각부터 핸들러에서 처리가 시작되는 시각까지의 시간

- 큐 상한 16 MiB는 720p 영상 12장이고 30/s에서 약 0.4초 분량이며 Q의 최댓값 389\~398ms와 일치
- 카메라 VGA는 16 MiB가 36장(약 1.2초 분량)이고 센서 100/s는 5초 막힘에 쌓이는 500건이 큐 상한 1,024건 미만
- iOS는 카메라 720p 700ms 막힘에서 29건(9.6%)을 폐기하고 처리량이 26.4건/초
- 이벤트 대기 시간 통계는 폐기한 이벤트를 포함하지 않으며 오래된 이벤트부터 폐기해 최신 값을 먼저 처리
- iOS는 큐가 차지 않는 조합에서 Q의 이벤트 대기 시간 상위 1%가 B보다 17ms 증가(카메라 VGA와 센서 700ms 막힘 모두 673ms에서 690ms)
	- 주의: 원인은 프레임 단위 처리로 추정하며 확인 못함
	- Android는 큐가 차지 않는 조합에서 B와 차이 없음
- 주의: 큐 크기 1,024건과 16 MiB는 측정 없이 정한 고정값
- 주의: 카메라 720p의 5초 막힘은 B가 처리 대기 한도에 닿아 발행이 108건에서 멈추므로 B의 값은 실제보다 짧을 가능성
- 주의: Android는 측정 중 다른 앱의 에뮬레이터 하나가 유휴 상태로 함께 실행 중

## 측정의 한계

- 주의: 시뮬레이터와 에뮬레이터에서만 측정해 실제 앱의 JS 부하와 UI 프레임 영향은 확인 못함
- 주의: JS 막힘 700ms와 5초, 카메라 720p 30/s, 센서 128B 100/s는 실제 앱의 빈도와 부하를 측정한 값이 아니라 가정한 값
